# Plan: v0.44.0 — "Everything from the audit" batch (11 features)

Ship all 11 feature gaps from the v0.44 audit in one release. Every gap is pure-frontend (no Rust changes), slots into existing patterns (pure helpers in `src/lib/`, views in `src/views/`, `mdpeek-*` localStorage settings, command-palette entries), and is verified against current line numbers.

## The 11 features

### Editor power

**1. Markdown table cell navigation** (~1 hr) — pressing Tab/Shift+Tab *inside* a table row jumps cell-to-cell instead of inserting indent.
- **`src/lib/editor-logic.js`** — new pure helper `tableCellNav(text, caret, dir)`:
  - Detect caret line matches `/^\s*\|.*\|\s*$/` (a table row). If not, return `null` (fall through to normal `handleTab`).
  - Parse cells by splitting on `|` (respecting leading/trailing pipes), find which cell contains the caret, move to next/prev cell start. If at last cell on Tab and there's a next row, move down; at first cell on Shift+Tab, move up.
  - Returns `{ caret }` (no text change — pure navigation) or `null`.
- **`src/views/editor.js`** Tab/Shift+Tab handler (~line 330) — call `tableCellNav` first; if it returns non-null, set caret and return; else existing `handleTab`.
- **`test/editor-logic.test.js`** — ~6 tests: not-a-table returns null, tab to next cell, tab at end of row wraps to next row, shift+tab to prev cell, shift+tab at start wraps to prev row, single-row table.

**2. Editor outline pane** (~1.5 hr) — a collapsible heading outline visible while editing, click to jump.
- **`src/lib/editor-logic.js`** — `extractHeadings(text)` already exists (line 511); reuse it.
- **`index.html`** — add `<aside id="editor-outline" class="editor-outline hidden">` next to the editor area; reuse `.reader-toc-item.level-N` classes from `src/styles/reader.css` so it inherits the tiered indent.
- **`src/views/editor.js`** — `buildEditorOutline(doc)` populates `#editor-outline` from `extractHeadings(doc.editor.getValue())`; click handler scrolls the textarea to the heading line (compute line offset via `indexOf`, then `scrollTo`/`setSelectionRange`). Debounced rebuild on editor change (reuse the existing change-listener debounce).
- **`src/main.js`** — toggle entry `toggle-editor-outline` (palette + toolbar button + `mdpeek-editor-outline` setting); persist + restore on load.
- No tests (DOM orchestration; smoke-tested). The heading extraction itself is already covered by existing `extractHeadings` tests.

### Writing aids

**3. Writing goal (word-count target)** (~1 hr) — set a word goal, see live progress in the status bar.
- **`src/lib/writing-goal.js`** (NEW) — pure helper:
  ```js
  export function goalProgress(words, goal) {
    if (!goal || goal <= 0) return null;
    const pct = Math.min(100, Math.round((words / goal) * 100));
    return { words, goal, pct, done: words >= goal, remaining: Math.max(0, goal - words) };
  }
  export const SESSION_KEY = 'mdpeek-writing-session';
  export const GOAL_KEY = 'mdpeek-writing-goal';
  ```
- **`src/main.js`**:
  - New command `set-writing-goal` (palette, around line 938) → `window.prompt` for a number → store in `GOAL_KEY`, snapshot current `wordCount()` into `SESSION_KEY`.
  - `updateEditorStatus()` (line 3980) — append a `goal 312/500 (62%)` chip to `#editor-status` when a goal is set, green when ≥100%. Reuses the existing `wordCount()`.
  - `clear-writing-goal` command to remove.
- **`test/writing-goal.test.js`** (NEW) — ~6 tests: null when no goal, basic pct, caps at 100, done flag, remaining, zero-words.

### Workspace / file management

**8. User document templates** (~2 hr) — let users save doc skeletons and create new docs from them.
- **`src/main.js`**:

  - `getTemplates()` / `saveTemplate(name, content)` / `deleteTemplate(name)` helpers (localStorage read/write + dispatch a `templates:changed` event).

- **`test/templates.test.js`** (NEW) — pure helpers `getTemplates`/`saveTemplate` extracted to `src/lib/templates.js` for testability (~5 tests: empty, add, overwrite by name, delete, malformed JSON recovers).

### Themes / appearance

**10. Theme scheduling (system / by-time)** (~1 hr) — auto-switch light/dark.
- **`src/main.js`**:
  - `THEME_MODE_KEY = 'mdpeek-theme-mode'` (`'manual'` default | `'system'` | `'time'`).
  - On init: if `system`, `matchMedia('(prefers-color-scheme: dark)').addEventListener('change', …)` → `applyTheme('dark'/'light')`. If `time`, an interval (every 5 min) picks dark if local hour < 7 or ≥ 19, else light — and runs once at startup.
  - `applyTheme` unchanged; the scheduler just calls it.
- **`index.html`** — appearance panel: a 3-way segmented control (Manual / Match system / By time) above the theme grid; the grid stays for manual override (selecting a card flips mode back to `manual`).
- **`test/theme-schedule.test.js`** (NEW) — extract the time-based decision to a pure helper `themeForHour(hour)` in `src/lib/theme-schedule.js` (~3 tests).

**11. Per-document theme override** (~1.5 hr) — pin a theme to one doc.
- **`src/lib/documents.js`** — add optional `theme` field to the doc object (set on creation/extension; `undefined` = inherit global).
- **`src/main.js`**:
  - `DOC_THEME_KEY = 'mdpeek-doc-themes'` (JSON map of `path → themeId`).
  - `renderActive` — before rendering, if the active doc has a path with an entry in the map, temporarily apply that theme to `:root` (set `data-theme`); on switch-away, restore the global `mdpeek-theme`. Track a `_docThemeActive` flag so `applyTheme` doesn't fight it.
  - Commands: `pin-doc-theme` (prompt picks from the 10 theme ids or current), `clear-doc-theme`.
- **`index.html`** — entry in the more-menu (`#more-menu`, line 81): "Pin theme to this doc" / "Clear pinned theme".
- **`test/documents.test.js`** — +2 tests for the theme-field round-trip through the map helpers (extracted pure `getDocTheme(path, map)`/`setDocTheme(path, theme, map)`).

## Risk
Low–medium. Every feature is additive (no existing behavior removed). The two integration-touching ones are:
- **F11 per-doc theme** modifies `renderActive`'s theme path — mitigated by a single guarded branch (`if _docThemeActive`) that restores the global on switch-away; if anything goes wrong the global theme still wins.
- **F4 toc-marker** adds a pre-pass to `renderMarkdown` — but it's gated on the presence of `[[toc]]` (no marker = zero behavior change) and runs before the existing `preprocessWikiLinks`, mirroring its exact pattern.

Everything else slots into new files or new palette entries without touching shared paths.

## Out of scope
- Multi-cursor editing, vim/emacs mode (large builds).
- Split view / side-by-side docs (layout rework).
- Math/LaTeX and mermaid already exist (verified in audit).
- Image gallery viewer, document statistics panel beyond the status bar.
