# Plan: v0.45.0 — "More new features" batch (13 features)

Ship 13 additive features in one release, grouped into 3 tiers. Every feature slots into existing patterns (pure helpers in `src/lib/`, views in `src/views/`, `mdpeek-*` localStorage, command-palette entries at `src/main.js:911-978`). All line numbers below verified against current source.

## Tier A — Rendering polish (5 features, all easy, ~3hr)

### A1. Subscript / superscript
Pandoc `H~2~O` and `x^2^` syntax. Clones the exact shape of `src/lib/highlight.js` (`==text==`→`<mark>`).
- **NEW `src/lib/subsup.js`** — `markedSubSup()` returning `{ extensions: [ {name:'sub', level:'inline', start, tokenizer, renderer}, {name:'sup', ...} ] }`. Regex `~(^\s|[~\n])...~` guarded to not match inside code spans (tokenizer only runs on inline text, same guarantee highlight.js relies on). `^` for sup is suppressed inside `$…$` math by checking the token's surrounding text doesn't sit between `$` markers (cheap heuristic; if uncertain, just render `^x^` everywhere outside fenced code — KaTeX's `$$` is block-level and won't collide).
- **`src/lib/renderer.js:198`** — `marked.use(markedSubSup())` next to `markedHighlightExt()`.
- **`src/styles/content.css`** — `sub { font-size: 0.75em; } sup { font-size: 0.75em; }` (browser defaults are fine; minimal tweak).
- **NEW `test/subsup.test.js`** — 5 tests: no-match passthrough, `H~2~O`, `x^2^`, code-span skip, adjacent pairs.

### A2. `!!! note` admonition syntax
mkDocs/Material/Obsidian convention. Reuses the existing GFM alert CSS (`.markdown-alert-*`) — no new styles.
- **`src/lib/renderer.js`** — NEW preprocessor `expandAdmonitions(md)` (mirrors `expandTocMarker` at line 76). Rewrites a leading `!!! TYPE` line + indented body into `> [!TYPE]` + blockquoted body, before marked sees it. Recognized types: `note, tip, info, warning, caution, important, abstract, success, question, failure, danger, bug, example, quote, done` (full mkDocs set) → mapped to the 5 GFM types for the icon, preserving the original keyword in the title.
- **`src/lib/renderer.js:357`** — add to the pre-pass chain (alongside `expandTocMarker` + `preprocessWikiLinks`), gated on presence of `!!!` so zero cost otherwise.
- **`test/renderer.test.js`** — +3 tests: no-marker passthrough, `!!! note`→alert, indented body preserved.

### A3. Image-size syntax
Both GitHub `![alt](src =200x300)` and Obsidian `![alt|300](src)` conventions.
- **`src/lib/renderer.js:204`** — extend the `image()` renderer. Parse a `=WxH` or `=W` suffix from `title` (GitHub puts size in title), and a `|W` suffix from `alt` (Obsidian). Strip the suffix from the displayed alt/title and emit `width`/`height` attrs. DOMPurify already allows these.
- **`test/renderer.test.js`** — +5 tests: no-size passthrough, GitHub `=200x300`, GitHub `=200` (width only), Obsidian `|300`, suffix stripped from alt.

### A4. Copy as plain text + Export to .txt
Factor the existing markdown-stripping regexes out of `wordCount` (`src/main.js:4238-4246`) into a shared, tested helper.
- **NEW `src/lib/strip.js`** — `stripMarkdown(text)` returns the 8-regex pipeline currently inline in `wordCount`. `wordCount` becomes a 3-line consumer.
- **`src/main.js:4236`** — `wordCount` calls `stripMarkdown(text)` then counts.
- **`src/main.js`** — `copyAsPlainText()` (mirrors `copyAsHtml` near line 3457) + `exportPlainText()` (mirrors `exportHtml` at line 1687). 2 palette entries near line 941: `copy-plaintext`, `export-txt`.
- **NEW `test/strip.test.js`** — 6 tests: fenced/inline code stripped, images stripped, links→label, headings/lists/emphasis/html stripped, CJK preserved, empty input.

### A5. Document statistics panel
Clone the existing editor-outline aside pattern (`index.html` + `main.js:4261-4316`).
- **NEW `src/lib/stats.js`** — `computeStats(text)` returns `{ words, chars, sentences, paragraphs, readMins, speakMins, avgWordsPerSentence, longWords }`. Reuses `stripMarkdown` (A4). Paragraphs = split on `\n\s*\n`; sentences = `match(/[.!?]+/g)`; speak rate 130 wpm.
- **`index.html`** — `<aside id="doc-stats" class="doc-stats hidden">` inside `.editor-wrap` mirroring `#editor-outline`.
- **`src/main.js`** — `rebuildDocStats()` populates it from `computeStats(doc.editor.getValue())`; debounced on editor change (same listener as outline). `toggleDocStats()` command + `mdpeek-doc-stats` setting.
- **`src/styles/base.css`** — `.doc-stats` reuses `.editor-outline` layout vars.
- **NEW `test/stats.test.js`** — 7 tests: counts, empty, CJK, multi-paragraph, sentence count, read/speak time, avg sentence length.

## Tier B — Editor power (5 features, medium, ~6hr)

- **`src/main.js:1498`** — in `closeTab(id)`, snapshot the doc into a module-level `_closedTabs` stack immediately before `store.close(id)`. Same hook in `closeDocs` (line 1540).
- **`src/main.js`** — `reopenClosedTab()` pops, calls `store.open({...})` with the snapshot. Palette entry `reopen-tab` at ~line 918, keybind **Ctrl+Alt+T** (Ctrl+` is terminal, Ctrl+Shift+T is typewriter — verified free).

### B2. Table formatter + sort-by-column
Markdown-table pipe alignment + sort rows by a column. Extends `tableCellNav` (v0.44).
- **`src/lib/editor-logic.js`** — NEW `formatTableBlock(text, startLine, endLine)` returns aligned text (computes max col width, pads cells, aligns `:---:` markers). NEW `sortTableRows(text, startLine, endLine, col, dir)` returns rows sorted (skips header + separator). Both return `{ text, start, end }` or `null` if not a table. Mirror `sortLines` (line ~440) shape.
- **`src/views/editor.js`** — detect the table block around the caret (consecutive `|...|` lines), call the helper, apply via `applyResult`.
- **`src/main.js`** — 2 palette entries: `format-table`, `sort-table-asc`/`sort-table-desc` (sort prompts for column or uses caret column).
- **`test/editor-logic.test.js`** — +8 tests: format aligns columns, format preserves alignment markers, format non-table→null, sort by col 0 asc/desc, sort numeric vs string, sort skips header, single-row table.

### B3. Smart text paste
The paste handler (`src/main.js:5999`) currently only catches images. Extend to smart text behavior.
- **NEW dep `turndown`** (~50KB, well-maintained HTML→Markdown lib) — add to `package.json`.
- **`src/lib/editor-logic.js`** — NEW `smartPaste({ text, html, url, hasSelection })` returns `{ text, start, end }` or `null` (fall through to default paste). Rules in priority order: (1) URL + selection → `[selection](url)`; (2) URL + no selection → paste URL as-is; (3) HTML containing `<table>`/`<ul>`/`<ol>`/`<h1-6>` → turndown to markdown; (4) else → null (plain paste).
- **`src/main.js:5999`** — in the paste handler, after the image branch, read `e.clipboardData.getData('text/html')` + `getData('text/plain')` + selection, call `smartPaste`, if non-null `preventDefault()` + insert. Add a `mdpeek-smart-paste` setting (default on) to disable.
- **NEW `test/smart-paste.test.js`** — 6 tests: URL+selection→link, URL no-selection→passthrough, HTML table→markdown table, HTML list→markdown list, plain text→null, disabled flag.

- **`test/autocomplete.test.js`** — +5 tests: trigger on `](#`, trigger on `[[#`, no-trigger on `(http:#`, candidate filtering, depth hint.

## Tier C — Ambitious (3 features, larger, ~7hr)

### C1. Local version history (snapshots)
Auto-snapshot each doc on save + a "Restore version…" picker. Fills the "no backup exists" gap.
- **`src-tauri/src/commands.rs`** — NEW `write_snapshot(path, content)` writes to `app_data_dir()/mdpeek/versions/<sha1(path)>/<unix-ts>.md`; NEW `list_snapshots(path)` returns `[{ ts, size }]` sorted desc. Pruning: `write_snapshot` keeps the 25 newest per path (deletes older). Reuse the existing `sha1`/`std::fs` patterns.
- **`src-tauri/src/lib.rs`** — register both commands in `invoke_handler`.
- **NEW `src/lib/snapshots.js`** — pure `snapshotKey(path)` (stable hash for folder name), `pruneList(entries, keep=25)` (sort desc, slice), `formatSnapshotTime(ts)` (relative: "2 min ago" / absolute). `SNAPSHOTS_KEY` not needed (server-side state).
- **`src/main.js`** — on successful save (existing save flow), fire-and-forget `invoke('write_snapshot', { path, content })`. New `restoreSnapshot()` command: lists snapshots via picker (reuse `makePicker`), on select shows preview + confirm, then `store.open` with the snapshot content (does NOT auto-overwrite the live file — user saves explicitly). Palette entry `restore-version`.
- **NEW `test/snapshots.test.js`** — 6 tests: snapshotKey stable, pruneList caps at 25, pruneList keeps newest, pruneList empty, formatSnapshotTime relative, formatSnapshotTime absolute.

### C3. Side-by-side reference pane (scoped down from full split-view)

The existing `.editor-pane`/`.preview-pane` split (`index.html:219-262`) already covers edit↔preview for one doc. So this feature targets the genuinely-missing use case: **open a second doc as a read-only rendered reference beside the doc you're editing.**
- **`src/lib/documents.js:152`** — add `this.secondaryId = null`; `setSecondary(id)` method; serialize/restore (line 237).
- **`index.html:219`** — add `<div id="reference-pane" class="reference-pane hidden"><header><span class="ref-title"></span><button class="ref-close">×</button></header><article class="ref-body"></article></div>` after `.preview-pane`, with a `<div id="ref-resizer">` between them.
- **`src/main.js`** — `openBeside(docId)` sets `store.secondaryId`, renders the doc's markdown into `.ref-body` via `renderMarkdown` + `enhanceDom`, shows the pane; `closeBeside()` hides it. Re-render reference pane when its doc changes (subscribe to store `change`). Palette entries `open-beside` (uses quick-switcher to pick a doc) + `close-beside`.
- **`src/views/tabs.js`** — context-menu item "Open beside" on a tab → `openBeside(id)`.
- **`src/styles/base.css`** — `.reference-pane` flex column, 30% width default, `#ref-resizer` reuses `.pane-resizer` styles.
- No unit tests (DOM orchestration); smoke-tested.

## Risk
**Low** for Tier A (all clone existing patterns exactly, additive).
**Low-Medium** for Tier B: B3 (smart paste) adds a dep + touches the paste handler but is gated behind `mdpeek-smart-paste` and falls through to default paste on any uncertainty; B2 (table ops) operates only inside detected table blocks (no-op outside, like `sortLines`).
**Medium** for Tier C:
- C1 (snapshots) is the only one with new Rust + a storage/pruning policy — mitigated by server-side pruning (keep 25), fire-and-forget on save (failure doesn't block save), and restore never auto-overwrites the live file.
- C2 (tag pane) reuses `acListTags` (already battle-tested by autocomplete); the only new surface is `folder-search.setInitialQuery` — additive, no behavior change if unused.
- C3 (reference pane) is scoped to read-only to avoid the editor-lifecycle surgery; the only store change is one new field + serialize line. If the re-render-on-`change` subscription proves buggy, the pane can render once on open with a manual refresh button as fallback.

Everything is additive — no existing behavior removed.

## Out of scope (explicitly)
- Multi-cursor editing (requires CodeMirror swap — the textarea is load-bearing across editor.js, editor-logic.js, find-bar.js, autocomplete-dropdown.js).
- Vim/emacs keybindings (same reason — libs need a real editor framework).
- MathJax option (KaTeX already covers math; adding a second engine doubles bundle for little gain).
- Full editable split-view (deferred per scope note in C3).
- CSV/markdown-table export (CSV viewer already exists at `src/views/csv-viewer.js`).
