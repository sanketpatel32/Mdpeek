### 3. Tab size config — 2 / 4 / 8 spaces (~45 min)
`INDENT = '  '` is hardcoded at `editor-logic.js:6`. Real complaint for users pasting 4-space docs.
- `src/lib/editor-logic.js` — replace `const INDENT` with a `getIndent()` that reads `localStorage.getItem('mdpeek-tab-size')` → `'    '` for `'4'`, `'\t'`... no, keep it simple: only 2/4/8 space strings. Update `handleTab`/`handleShiftTab`/`indentLines` to call `getIndent()`. Keep the `prefix` param plumbing that already exists in `indentLines`.
- `index.html` editor settings card (~line 826, after Code block line numbers) — add a `<select id="settings-tab-size">` with 2/4/8 options, mirroring the font-family select pattern.
- `src/main.js` settings wiring (~line 4607) — add change listener that writes `mdpeek-tab-size` and re-dispatches an input event on the editor so the gutter re-syncs. Add `'mdpeek-tab-size'` to the reset-key list.
- `src/main.js` `syncSettingsControls()` (~line 4410) — sync the select's value from localStorage.
- Default: 2 spaces (preserves current behavior).

### 7. Reader scroll position memory (~20 min)
Re-entering Reading Mode always jumps to top (`main.js:1779`). Users lose their place.
- `src/main.js:1807` `exitReading()` — before clearing, capture `doc.readerScrollY = scroll.scrollTop` onto the doc object.
- `src/main.js:1779` `enterReading()` — replace `scroll.scrollTop = 0` with `scroll.scrollTop = doc.readerScrollY || 0`.
- The scroll listener from v0.36.0 (`setupReaderProgressTracking`) keeps the value fresh, so reading it on exit is reliable.
- No persistence across app restarts (the doc object is in-memory only) — acceptable for a first cut; matches how view-mode `doc.scrollY` already behaves.

## Go-to-line (Ctrl+G) — explicit conflict resolution

**Decision: reassign Ctrl+G → go-to-line; find-next stays on F3 only.**
- Current: `Ctrl+G` = find-next (`main.js:5129`), `Ctrl+Shift+G` = find-prev.
- After: `Ctrl+G` = go-to-line, `Ctrl+Shift+G` = find-prev (unchanged), F3/Shift+F3 = next/prev (unchanged), Enter-in-find-bar = next (unchanged). Nothing is actually lost.
- Matches VS Code / Sublime convention. Will note in CHANGELOG.
- Implementation: extract the line→offset+scroll math from `applyPendingLine` (`main.js:1127-1152`) into a reusable `scrollEditorToLine(doc, line)`. Build a tiny prompt — reuse `window.prompt('Go to line:')` for the simplest version (no new modal chrome). On confirm, parse the int and call the helper. Add palette entry `{ id: 'goto-line', label: 'Go to line…', hint: 'Ctrl+G', run: gotoLine }`.
- Edit-mode only (the prompt + setState path); toast "Switch to edit mode" otherwise.
