# Plan: Terminal — fix close-freeze + theme polish (v0.43.0)

Two asks, both well-understood from the audit: (1) the "Not Responding on close" bug has a concrete root cause, and (2) the terminal's colors/shadows are hardcoded so they look wrong on several themes.

## Part A — Fix the close freeze (root cause)

**Root cause** (two reinforcing bugs):

1. **`destroyAll()` re-spawns a PTY during shutdown** (`src/views/terminal.js:490-494`). It calls `closeTab()` per tab, but `closeTab()` (line 339-343) **re-creates a fresh tab + spawns a new PTY** when the last tab closes. So on quit, `destroyAll` fires a brand-new `spawn_terminal` (15s race) milliseconds before `app.exit(0)` — the spawn collides with WebView2 teardown and the window hangs.
2. **`kill_terminal` holds the state Mutex across `_child.kill()`** (`src-tauri/src/pty.rs:232-237`). On Windows ConPTY, `Child::kill()` → `TerminateProcess` can stall (interactive PowerShell, AV scan, profile unload). While it stalls, *every* terminal IPC queues behind the lock → the whole app looks frozen.

**Fix 1 — JS: stop `destroyAll` from respawning.** Add an options arg to `closeTab` so the "last tab → recreate" branch is skipped during teardown:
```js
function closeTab(id, e, opts = {}) {
  // ...existing dispose logic unchanged...
  tabs = tabs.filter((t) => t.id !== id);
  if (tabs.length === 0 && !opts.destroy) { createTab(); return; }
  // ...
}
destroyAll() {
  [...tabs].forEach((t) => closeTab(t.id, null, { destroy: true }));
  // Drain the backend in one shot (Fix 2 below) instead of N fire-and-forget kills.
  invoke('kill_all_terminals').catch(() => {});
  bootstrapped = false;
}
```

**Fix 2 — Rust: kill off the lock + add `kill_all_terminals`.** Move `_child.kill()` off the IPC thread so a slow ConPTY teardown can't block other commands, and add a single drain-all command for shutdown:
```rust
#[tauri::command]
pub fn kill_terminal(state: tauri::State<'_, TermState>, id: u32) -> Result<(), String> {
    // Remove under the lock (fast), kill on a worker thread so a slow
    // TerminateProcess can't block terminal IPC.
    let entry = state.0.lock().unwrap_or_else(|e| e.into_inner()).remove(&id);
    if let Some(mut entry) = entry {
        std::thread::spawn(move || { let _ = entry._child.kill(); });
    }
    Ok(())
}

#[tauri::command]
pub fn kill_all_terminals(state: tauri::State<'_, TermState>) -> Result<(), String> {
    let entries: Vec<TermEntry> = state
        .0 .lock().unwrap_or_else(|e| e.into_inner())
        .drain().map(|(_, v)| v).collect();
    std::thread::spawn(move || {
        for mut entry in entries { let _ = entry._child.kill(); }
    });
    Ok(())
}
```
Register `kill_all_terminals` in `src-tauri/src/lib.rs` alongside the other pty commands. `TermEntry` is already `Send` (master/writer/child all `Send`), so the move into `thread::spawn` compiles.

**Result of A:** on quit, `destroyAll` disposes xterm locally + one `kill_all_terminals` call drains the map on a worker thread; when `quit_app` → `app.exit(0)` drops `TermState`, the map is already empty so nothing blocks. No respawn race, no lock contention.

## Part B — Theme polish (look great on all themes)

The audit found the ANSI colors are hardcoded in JS, and several CSS rules use hardcoded shadows/tints that only look right on dark themes.

**B1 — Derive ANSI colors from theme tokens** (`src/views/terminal.js:47-71`). Each theme already tunes `--alert-*` and `--success` to its signature palette (Dracula green `#50fa7b`, Solarized yellow `#b58900`, Nord cyan `#88c0d0`, etc.), but `xtermThemeFromApp()` ignores them and hardcodes Tailwind colors. Reuse them:
```js
export function xtermThemeFromApp() {
  const fg = readCssVar('--fg', '#e8e8e8');
  const bg = readCssVar('--bg', '#000000');
  const muted = readCssVar('--fg-muted', '#888');
  const red     = readCssVar('--danger',          '#ff5555');
  const green   = readCssVar('--success',         '#50fa7b');
  const yellow  = readCssVar('--alert-warning',   '#f1fa8c');
  const blue    = readCssVar('--accent',          '#8be9fd');
  const magenta = readCssVar('--alert-important', '#ff79c6');
  const cyan    = readCssVar('--alert-note',      '#8be9fd');
  return {
    background: bg, foreground: fg, cursor: fg, cursorAccent: bg,
    selectionBackground: readCssVar('--surface-active', 'rgba(255,255,255,0.2)'),
    black: muted, white: fg,
    red, green, yellow, blue, magenta, cyan,
    brightBlack: muted, brightWhite: fg,
    brightRed: red, brightGreen: green, brightYellow: yellow,
    brightBlue: blue, brightMagenta: magenta, brightCyan: cyan,
  };
}
```
Keeps `red→--danger` and `blue→--accent` (the two mappings the existing test asserts), so the test stays green; only the arbitrary fallback strings change (test updated to match).

**B2 — Theme-aware CSS** (`src/styles/base.css:4742-4891`):
- `.terminal-drawer` shadow `rgba(0,0,0,0.25)` → `0 -8px 24px color-mix(in srgb, var(--fg) 12%, transparent)` (theme-tinted, supported in WebView2/Chromium 111+).
- Drop `backdrop-filter: blur(12px)` (bg is opaque → does nothing, costs perf in WebView2).
- `.terminal-tab-close:hover` hardcoded `rgba(255,255,255,0.15)` → `var(--danger)` bg + `var(--bg-elevated)` fg (proper close affordance, works on every theme).
- `.terminal-tab.active` + accent underline: `box-shadow: inset 0 -2px 0 var(--accent)`.
- `.terminal-resize-handle`: add a thin always-visible center bar via `::after` (subtle `--border-subtle`, brightens to `--accent` on hover) instead of flooding the whole 8px strip.

   - Close the last terminal tab in-app → a fresh tab still appears (the non-destroy path is unchanged).

5. Ship as **v0.43.0** (patch — bug fix + visual polish; no API/behavior change users depend on).

## Risk
Low. The freeze fix is strictly more robust (off-lock kill, no respawn-on-shutdown). The theme change is additive color mapping. The only behavior change visible to a user is "terminal colors now match the theme" and "closing tabs during normal use still recreates an empty tab" (preserved). `color-mix` is supported in all WebView2 builds Tauri 2 ships on Win10/11.

## Out of scope
- Custom per-theme 16-color ANSI override vars (`--term-red` etc.) — the alert-var reuse gets 90% of the benefit at 0% of the lines; can add later if a theme looks off.
- Tab drag-reorder, split panes, shell picker — separate batches.
