# v0.51.0 — OS notifications + snapshot diff view

Two high-impact, self-contained features. Both confirmed net-new (audited across editor, docs/views, and platform-integration surfaces). Both reuse existing infrastructure (the toast system, `snapshots.js`, the snapshot picker, the `makePicker` factory). Picked from the user-impact × feasibility shortlist because:
- **OS notifications** fills the most glaring gap for a tray app (Pomodoro-end, export-done, file-changed-while-minimized all currently fire only in-app toasts — invisible when minimized).
- **Snapshot diff** makes existing version history actually reviewable (snapshots exist but can only be opened whole in a new tab — no way to compare).

Current state verified: v0.50.0 shipped (HEAD `25075de`, 962 tests green). Next release is **v0.51.0** (minor — new features).

## F1. OS notifications (`tauri-plugin-notification`)

Add the official Tauri notification plugin and fire native OS notifications (with sound, action-center entry) for the three events that today silently toast. Gated by a settings toggle so users can opt out.

**Rust side**
- `src-tauri/Cargo.toml` — add `tauri-plugin-notification = "2"`.
- `src-tauri/src/lib.rs` — register `.plugin(tauri_plugin_notification::init())` in the builder (near the other `.plugin(...)` calls, ~line 122).
- `src-tauri/capabilities/default.json` — add `"notification:default"` to `permissions`.
- No new Rust commands needed — the plugin is invoked from JS.

**New pure helper — `src/lib/notify.js`**
A thin, fail-safe wrapper around `@tauri-apps/plugin-notification` so the rest of the app doesn't import the plugin directly:
- `osNotificationsEnabled()` — reads `localStorage['mdpeek-os-notifications']` (default off; opt-in since it prompts for OS permission).
- `async notifyOs({ title, body })` — checks the gate; if on, calls `isPermissionGranted()` → `requestPermission()` (first time) → `sendNotification({title, body})`. Wrapped in try/catch (plugin unavailable in dev/browser → silent no-op). Returns a boolean (sent or not) so callers can fall back to a toast when the OS notification didn't fire.
- Pure-ish (touches localStorage + plugin, but no DOM) — unit-tested by injecting a fake `plugin` module shim (matching how `doc-theme.js`/`sessions.js` inject their store). The actual OS call is behind the injectable boundary.

**`src/main.js`**
- Import `notifyOs` + `osNotificationsEnabled`.
- Add a `notify(title, body)` orchestrator helper that tries the OS notification first, then **always** also toasts (so the in-app signal is never lost). This is the single chokepoint — all three call sites use it.
- **Pomodoro completion** (line 3916-3918): the `toast(\`${pomoPhaseLabel(r.completed)} complete!\`)` becomes `notify('Pomodoro', \`${pomoPhaseLabel(r.completed)} complete!\`)`.
- **File changed on disk while unsaved** (line 7683 area, the "your unsaved edits were kept" toast): upgrade to `notify(...)` so a backgrounded user learns their file changed.
- **Export complete** — currently no toast on *success*. Add `notify('Export complete', '<filename>')` after `exportPdf`/`exportHtml`/`exportPlainText` return successfully (gated so it doesn't fire for instant operations — only the slow PDF path really needs it, but cheap to add to all three).
- Settings: add a `.setting-row` checkbox `#settings-os-notifications` in the General panel, bound to `mdpeek-os-notifications`. On enable, proactively call `requestPermission()` so the OS prompt fires immediately (not deferred to first notification).

**Test — `test/notify.test.js`**
- `osNotificationsEnabled` default + opt-out reading.
- `notifyOs` no-op when disabled; calls the injected plugin's `sendNotification` when enabled + permission granted; handles permission-denied; swallows plugin errors (never throws).

## F2. Snapshot diff view

Compare a saved snapshot against the current doc (or two snapshots) in a side-by-side modal. Makes version history reviewable. Reuses `list_snapshots`/`read_snapshot` + a new pure LCS-based line diff.

**New pure module — `src/lib/diff.js`**
Line-level diff via the classic LCS (longest-common-subsequence) dynamic-programming algorithm — dependency-free, well-established, O(n·m) which is fine for documents (snapshots are per-doc, bounded):
- `diffLines(oldText, newText)` → `{ rows: [{ type: 'equal'|'add'|'del', oldLine?, newLine?, text }], stats: { added, removed } }`. Splits on `\n`, walks the LCS backtrack path, emits aligned rows. Pure, no DOM.
- `formatDiffStats(stats)` → human string like `"+12 −3"` for headers.
- Non-throwing on empty/null input (returns empty diff).

**New view — `src/views/diff-viewer.js`**
Mirrors the singleton-panel shape (`build()` once, `init/open/close/destroy`):
- `initDiffViewer()` returns `{ open, close }`.
- `open({ title, oldContent, newContent, oldLabel, newLabel })` builds a two-pane `<div class="diff-pane">` layout (old on left, new on right, scroll-synced), each pane a list of `.diff-row.diff-{type}` rows. Header shows title + `formatDiffStats`. A footer with "Use this version" (copies the `new` side to the active doc + closes) and "Close".
- Lives in a modal overlay (`.diff-overlay`) appended to `document.body`, Esc-to-close, matching the reference-pane/tag-pane singleton convention.

**`src/main.js`**
- Import `initDiffViewer`, instantiate once.
- Extend the snapshot picker flow (`restoreSnapshot`, line 1339): after building the entries list, also expose a **"Compare with current"** affordance. Concretely: add a second palette command `{ id: 'diff-version', label: 'Compare version…', run: diffVersion }` where `diffVersion()` lists snapshots (reuse the same `list_snapshots`+`toSnapshotEntries` path) in a picker; on select, `read_snapshot` → open the diff viewer with `{oldContent: snapshot, newContent: doc.editor.getValue(), oldLabel: 'Snapshot …', newLabel: 'Current'}`.
- The existing `restore-version` command stays as-is (open-whole-snapshot) — diff is additive, not a replacement.

**CSS — `src/styles/base.css`**
- `.diff-overlay` (modal), `.diff-header`, `.diff-grid` (two columns, scroll-synced), `.diff-pane`, `.diff-row` with `--diff-add-bg`/`--diff-del-bg` (tinted backgrounds using `color-mix`), `.diff-line-num`, `.diff-actions`. Match the modal styling of the existing `.modal-overlay`.

**Test — `test/diff.test.js`**
- `diffLines`: identical → all `equal`; pure addition → `add` rows at the end; pure deletion; mid-document change (del+add pair); empty old / empty new; `stats.added`/`stats.removed` counts.
- `formatDiffStats`: formatting + zero case.
